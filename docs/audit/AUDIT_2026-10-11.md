## How this audit was performed

- **Static review** of every area of the repository: physics/numerics,
  C API/MPI/I-O/restart, build/CI/packaging and test/qualification tooling.
  Each area was reviewed independently, and the high-impact findings were then
  re-checked by reading the code directly.
- **Native build.** The tree was configured and built in Debug with GNU Fortran 13.3,
  OpenMPI 4.1.6 and HDF5 1.10.10 (Ninja, 780/780 targets, no errors).
  - Pinned dependency revisions were cloned with git, because GitHub archive URLs and
    `mumps-solver.org` were unreachable from the sandbox.
  - MUMPS came from the **system MUMPS 5.6.2** through a local shim, not the pinned
    5.9.1. These native results are therefore *diagnostic*, not qualifying.
- **CTest without reference data.**
  - Every locally runnable test passed (123 tests).
  - The only failures were the 9 reference-data downloads, which were blocked by the
    sandbox network, and the 36 simulations that depend on them.
  - Rebuilding with `-Dgemini3d_midpoint_conduction=ON` also compiled, and 98/98
    non-simulation tests passed.
  - A separate Release build with numpy/scipy/h5py installed passed 136/136 `unit`
    tests and 83 standalone Python qualification tests.
- **Not executed.** None of the nine reference simulations, hosted CI, or the
  macOS, Windows/WSL and Intel paths could run here.

## 2. Physics and numerics

### 2.1 Inherited correctness defects

**P1 — Critical (science) — ✔ [UPSTREAM]: gravitational current corrupts J3.**
- **Where:** `src/numerical/potential/potential_comm_mumps.f90:561-562`
- **Evidence:**
  ```fortran
  J2(1:lx1,1:lx2,1:lx3)=J2(1:lx1,1:lx2,1:lx3)+sigPgrav*g2-sigHgrav*g3
  J3(1:lx1,1:lx2,1:lx3)=J2(1:lx1,1:lx2,1:lx3)+sigHgrav*g2+sigPgrav*g3   ! J2, not J3
  ```
  This is a copy-paste error. Every run with `flaggravdrift=.true.` (equatorial
  plasma bubbles, Rayleigh–Taylor) replaces the accumulated conduction, wind and
  pressure J3 with J2 plus the gravity term. That corrupts the source term of the
  potential equation.
- **Fix:** `J3(...)=J3(...)+sigHgrav*g2+sigPgrav*g3`. Add a unit test that compares
  J2/J3 with hand-computed values, and report it upstream.

**P2 — Critical (science) — ✔ [UPSTREAM]: default vibrational cooling sign inverted.**
- **Where:** `src/sources/sources.f90:545-553`. This is the `flagevibcool==0` branch,
  which is the default (`config_nml.f90:131,413`).
- **Evidence:** `fact = sfact*2.99e-12*...*(exp(-g*(Te-Tn)/Te/Tn)-1)` is followed by
  `iePT=iePT-max(fact,0)`. The O2 term has the same pattern.
  - Because g>0, `fact<0` whenever Te>Tn, so `max(fact,0)=0` and no cooling is applied.
  - Checked numerically: at Te=1500 K, Tn=800 K, fact=−6.9e-13 and 0 is subtracted.
  - At Te=600 K, Tn=800 K, fact=+4.7e-14, so electrons that are already colder than
    the neutrals are cooled further.
- **Impact:** the main E/F1-region electron cooling channel is missing whenever
  electrons are heated (aurora, Joule heating, STEVE/SAID), so Te is biased high.
- **Fix:** `iePT = iePT + min(fact, 0._wp)`, or simply `+ fact`, for both N2 and O2.
  This needs science review and a reference refresh.

**P3 — High (science) — ✔ [UPSTREAM]: wrong neutral species in O2⁺+N2.**
- **Where:** `src/sources/sources.f90:196`
- **Evidence:** `betanow=5e-16_wp*nn(:,:,:,3)*1e-6_wp`. Index 3 is O2; N2 is index 2,
  as the rotational terms at lines 522/525 and `N2vib` confirm. The rate therefore
  scales with n(O2) instead of n(N2), which is roughly 4× too small in the lower
  thermosphere.
- **Fix:** use `nn(:,:,:,2)`.

**P4 — High for the opt-in path — ● / ? [UPSTREAM]: `flagevibcool=1` path.**
- **`STerm1` discarded (●):** at `sources.f90:775-776` and `788-789`, the v=1 term
  reuses `Sterm0`, so `STerm1` is computed and then discarded.
- **Probable unit error (?):** at `sources.f90:529-531`, `N2/O2VibrationalLoss` are
  subtracted without `sfact = e/kB·(γ−1) ≈ 7.7e3 K/eV`. The rotational terms in the
  same branch, and the analogous vibrational terms in the default branch, do apply it.
  To confirm, check the units of Q in the Pavlov (1998) and Jones et al. (2003) fits.
- **Dead branch:** the `Tei>6000` branch is unreachable because of `Te=min(Ts,6000)`
  at line 747.

**P5 — Medium — ✔: background E0 added two cells off in `BGfield_Lagrangian`.**
- **Where:** `src/libgemini_mpi.f90:331-333`, plus the prints at 339 and 449-452.
- **Evidence:** `E1=>electrovars(:,:,:,1)` is a section pointer, so its lower bound
  is 1 while `electrovars` starts at −1. As a result, `E1(1:lx1,1:lx2,1:lx3)` covers
  ghost-inclusive cells −1..lx1−2.
- **Impact:** for non-Lagrangian runs with `flagE0file=1`, the initial E field and
  drifts are shifted by two cells in every dimension, and the last two interior cells
  get no E0. `electrodynamics()` recomputes E each step, so the effect is mainly on
  the initial state and the first step.
- **Fix:** index `E1(3:lx1+2,3:lx2+2,3:lx3+2)`, or pass the arrays to a helper with
  `(-1:)` dummies.

**P6 — Medium — ?: neutral frictional heating share.**
- **Where:** `src/sources/sources.f90:1092-1102` (`srcsEnergy_neut`)
- **Evidence:** it appears to credit the neutral with the ion's mass share,
  `mn/(ms+mn)` rather than `ms/(ms+mn)`, and to scale by `1/(γn−1)`. Ion plus neutral
  frictional heating then does not sum to ρν|Δu|². This matters for the coupling
  outputs to neutral models.
- **Fix:** verify against the Schunk & Nagy form
  Q_n = ρ_s ν_sn/(m_s+m_n)·[3k(T_s−T_n) + m_s|Δu|²], then correct if confirmed.

**P7 — Medium — ? [UPSTREAM-era]: split chemistry is not species-conservative.**
- **Where:** `sources.f90:19-325`, `multifluid.f90:754-773`
- **Evidence:** each species is advanced with ETD using a frozen P and L, so for stiff
  exchange channels the product gain and the reactant loss differ. Re-summing nₑ
  afterwards hides this from the charge balance.
- **Fix:** add a total-ion-inventory ledger, and consider a pairwise or
  Patankar-type update for exchange reactions.

**P8 — Medium — ●: production collision exchange is not reciprocal.**
- **Where:** `sources.f90:503-514`, `collisions.f90:43-51`
- **Evidence:**
  - Energy exchange uses each species' own `1/(γs−1)`, so it cancels only when γa=γb.
    This affects O⁺/NO⁺ and e/molecular-ion pairs.
  - The `Csj` table violates m_a·Csj(a,b)=m_b·Csj(b,a) by up to about 5%
    (N2⁺/O2⁺ 1.050, O⁺/N2⁺ 0.952).
- **Fix:** see N5. The new `pair_exchange` operator is the intended remedy, but it is
  not wired in yet.

**P9 — Low/Medium — ●: electron thermal conductivity is uncapped.**
- **Where:** `collisions.f90:223-228`
- **Evidence:** the factor `(1-1.21e-4*Ts)` turns negative above about 8264 K.
  `thermal_conduct_new` caps it. Separately, `energy_diffusion` (`multifluid.f90:460`)
  ignores `cfg%flagevibcool` when it chooses the conductivity routine, while
  `diffusion_source_loss_energy` (650-654) honours it.
- **Fix:** cap the factor consistently, and select the conductivity routine the same
  way in both paths.

**P10 — Low — ?: x1 forward difference uses the ghost spacing.**
- **Where:** `src/numerical/calculus/gradient.f90:67,140`
- **Evidence:** `(f(2)-f(1))/dx1(1)` uses the spacing between the ghost and the first
  cell. The x2/x3 and divergence routines use `dx(2)`. This affects cell 1 of the
  ambipolar and pressure forces on non-uniform x1 grids.
- **Fix:** use `dx1(2)` once the spacing convention is confirmed.

**P11 — Low: other numerics defects.**

### 2.2 Recent change `083726a` [NEW]

**N0 — verified OK.**
- The `coulomb_colln` Φ series (`collisions.f90:178-183`) has correct coefficients:
  3/W³∫₀ᵂx²e^{−x²}dx = 1 − 3/5W² + 3/14W⁴ − …
- At the W=0.1 switch, the closed form's relative error is about 2e-14.

**N1 — Medium — ✔: default solver path changed.**
- **Where:** `PDEparabolic.f90:173-174,264-265,399-400,444-481`
- **Evidence:** `eliminate_dirichlet_columns` and `scale_interior_rows` are applied
  unconditionally to `TRBDF21D` and `backEuler1D`, which every build uses.
  - Algebraically the transformation is exact.
  - It can change LAPACK pivoting, and so round-off-level results, in the frozen
    reference path. That is not behind `gemini3d_midpoint_conduction`.
  - The commit message ("testing…") does not disclose it.
- **Fix:** either gate it, or record a full nine-case native reference run with it and
  document it as a solver change.

**N2 — Medium — ●: the midpoint path aborts the process.**
- **Where:** `nonlinear_diffusion.f90:25,33-34,36`
- **Evidence:**
  - `error stop` fires on a non-positive predictor or conductivity. That is reachable
    from `energy_diffusion_C`.
  - The standard path tolerates undershoot and floors temperature at 100 K. The
    midpoint path kills the run instead, with no dump, after earlier species have
    already been updated.
  - Positivity of the backward-Euler predictor is not guaranteed for electrons: the
    central-differenced thermoelectric term loses the M-matrix property when the cell
    Péclet number exceeds 2 (?).
- **Fix:** return a status, or use the project's dump-then-stop helper. Consider an
  upwinded thermoelectric term in the predictor.

**N3 — Medium — ●: the midpoint qualification never exercises electrons.**
- **Where:** `test/qualification/midpoint_diffusion_probe.f90:58,115,125`
- **Evidence:** only isp=6 is tested, with `nn=0`, `J1=0` and h=1. The genuinely
  nonlinear paths are untested: the electron λ(nₑ,nₙ), β≠0, and the λ-dependent heat
  flux Neumann ghost.
- **Fix:** add an isp=7 fixture on a non-uniform or dipole metric, with a time-order
  check.

**N4 — Low — ●: the midpoint path costs about twice as much and allocates per call.**
- **Where:** `multifluid.f90:460-462`, `nonlinear_diffusion.f90:26-27`
- **Evidence:** `energy_diffusion` still builds the standard coefficients and then
  discards them. The midpoint routine allocates 9 work arrays per species per step.
- **Fix:** branch before building the coefficients, and preallocate the work arrays.

**N5 — Medium — ●: `pair_exchange` is correct but unused.**
- **What checks out:** independently checked, the operator conserves momentum and
  total energy exactly. The thermal convolution term matches the exact linear ODE
  solution, and the integrator is unconditionally stable.
- **The problem:** it has no production caller (only `pair_exchange_probe.f90`), yet it
  is linked into `libgemini3d`.
- **Fix:** wire it in behind an opt-in switch, the same pattern as midpoint conduction,
  to replace the non-reciprocal production exchange (P8), and qualify it with the
  existing ledgers.

**N6 — Medium — ✔: the midpoint option leaves no provenance.**
- **Where:** `options.cmake:25`
- **Evidence:** `gemini3d_midpoint_conduction` is compile-time only. It is absent from
  `feature_summary`, from `gemini_features`, from output and restart metadata, and
  from the `qualification-*` presets. A cached `ON` survives a re-run with
  `--preset qualification-*`.
- **Fix:** set it explicitly OFF in the qualification presets, stamp it into the
  outputs, and add a non-gating CI build with it ON.

**N7 — Low — ●: the stage-3 temperature-floor audit is inconsistent.**
- **Where:** `multifluid.f90:289-290` vs `478,482,708`
- **Evidence:** stage 3 uses raw `ns` for heat capacity while stages 1–2 use
  `max(ns,mindensdiv)`. It is also a silent no-op unless `mass_active` is set, which
  is the case for C-API hosts.

**N8 — Low — ✔: the commit mixes unrelated changes.**
- **Evidence:** one commit titled "testing an update for local continuity enforcement"
  carries all of these:
  - new physics;
  - a default-solver change;
  - an HWM14 pin bump;
  - MPI build policy (`gemini3d_fail_mpif08` default ON);
  - CI action relocation;
  - build artifacts;
  - a 95 KB self-copy of its own diff.
- **Fix:** split future changes so each can be reviewed and reverted independently.

## 3. C API, MPI, I/O and restart

**AGENTS.md compliance — ✔ OK in all built code.**
- Every boolean at an active `bind(C)` boundary is `integer(C_INT)`, converted with
  `/= 0` and `merge(1,0,…)`.
- `struct params` matches `type(c_params)`, including `ymd` at offset 1016.
- The only `C_BOOL` is an unused import in the unbuilt `app/main.noenergy.f90:17`
  (see C21).

**C1 — High (design) — ●: no error channel in the C API, and no `MPI_Abort`.**
- **Evidence:**
  - About 536 `error stop` sites, plus `stop`/`MPI_Finalize` in `check_dryrun`
    (`libgemini_mpi.f90:280-293`), are reachable from the `*_C` wrappers. A C/C++
    host cannot recover or clean up.
  - There is no `MPI_Abort` anywhere. Root-only aborts leave workers blocked in
    collectives: `libgemini_mpi.f90:195`, `temporal_mpi.f90:104-105` and
    `plasma_input.f90:76`. Under Slurm's default settings the job hangs until
    walltime.
- **Fix:** add a single `gemini_abort(msg)` that calls `MPI_Abort`, and an
  `integer(C_INT) :: status` (or last-error) channel on the C wrappers, per the
  AGENTS.md convention. Library code should never call `stop` or `MPI_Finalize`.

**C2 — Medium — ✔: `solar_ionization_C` arity mismatch.**
- **Evidence:** the Fortran wrapper takes 10 arguments (`libgemini_c.f90:1146-1158`).
  `include/gemini3d.h:101` and `app/main.cpp:323` pass 8.
- **Impact:** it works only because `gavg`/`Tninf` are never dereferenced.
- **Fix:** remove the two dummies, or add them to the header. Extend
  `test/audit/cabi_test.cpp` with arity checks generated from the Fortran interfaces.

**C3 — Medium — ✔: every rank writes the same non-finite dump file.**
- **Where:** `src/libgemini.f90:1695`
- **Evidence:** `check_finite_output(...,999,...)`, so all ranks write
  `dump_nonfinite_output_worker_999.h5` and collide.
- **Fix:** pass the real rank.

**C4 — Medium — ●: published outputs and checkpoints are mode 0600.**
- **Where:** `src/io/atomic_file.f90:27-36`
- **Evidence:** `mkstemp` and then rename keep mode 0600 regardless of umask. That
  breaks group-shared HPC project directories and collaborator post-processing.
- **Fix:** `fchmod(fd, 0666 & ~umask)` after `mkstemp`.

**C5 — Medium — ?: uninitialized ghost cells make exact-restart saves heap-dependent.**
- **Evidence:**
  - `Phiall` is allocated without initialization (`libgemini_mpi.f90:74`) and its
    ghosts are broadcast.
  - `app/main.cpp:165-167` uses `std::malloc` for state, while Fortran zero-fills.
  - The restart `check_payload` requires *all* of `electro`, ghosts included, to be
    finite.
- **Fix:** `allocate(..., source=0._wp)`, and `std::calloc`/`std::vector`.

**C6 — Medium — ●: initial-condition finiteness and range checks cover only the root's slab.**
- **Where:** `src/io/plasma_input.f90:76`
- **Evidence:** this contradicts `docs/Readme_audit.md`, which says all species and
  partitions are checked.
- **Fix:** check `nsall/vs1all/Tsall` on root before broadcast, or check on every rank
  followed by a collective flag.

**C7 — Medium (design) — ●: C wrappers size arrays from module globals.**
- **Evidence:** the `lx1/lx2/lx3` used by `c_f_pointer` come from module variables,
  not from the caller.
- **Impact:** with the module state (`it`, `v2grid`, `mpi_cfg`, …), only one
  simulation instance and one patch size per process is possible. A ForestClaw-style
  host passing other sizes would silently go out of bounds.
- **Fix:** pass the dimensions explicitly (as `interp3_C` already does) or store them
  in the work handle, and document the single-instance limitation.

**C8 — Medium — ✔: `gemini3d.run` advertises `-n` but does not implement it.**
- **Where:** `src/utils/exe_frontend.in.f90:295` and `cli_parser`
- **Evidence:** the help text lists `-n`, but `cli_parser` has no `-n` case, so it
  hits "unknown option". `cpu_count()` is never called, so on a workstation without
  scheduler variables `Ncpu` silently defaults to 1.
- **Fix:** implement `-n`, and fall back to `cpu_count()`.

**C9 — Medium — ●: `magcalc` misreads times.**
- **Where:** `src/utils/magcalc_cli.in.f90:208,221`
- **Evidence:** `-start_time/-end_time` are read with `'(F9.3)'`, so `36000` is read
  as `36.0`.
- **Fix:** use list-directed reads with range checks.

## 5. Tests and qualification tooling

**T1 — High — ✔: negative tests cannot detect what they guard.**
- **Where:** 16 tests under `test/audit/CMakeLists.txt:25,38,45,76,91,126`
- **Evidence:** they use bare `WILL_FAIL`, so any nonzero exit passes: an oracle
  mismatch, a misspelled mode, or an MPI launch failure. For example, if the `cflcalc`
  zero-metric guard were removed, `cfl_probe.f90:17` would stop with
  "oracle mismatch" and the test would still pass.
- **Fix:** use `PASS_REGULAR_EXPRESSION` with the exact library message, or a wrapper
  that checks both the exit code and the message.

**T2 — High — ●: `qualification:midpoint_diffusion` works only with Ninja, static libraries and GNU.**
- **Evidence:**
  - `run_physics_native.py` and `trace_diffusion_stages.py` scrape
    `ninja -t commands`.
  - They assert that `libgemini3d.a` exists.
  - `run_physics_native.py:21` hard-codes `-fcheck=all -ffree-line-length-none`,
    without Intel's mandatory `-fpscomp logicals`.
  - Compiler detection is a name heuristic.
- **Impact:** under the Makefiles generator (the README quick start, the `gmake` preset)
  or with `BUILD_SHARED_LIBS=ON`, the test fails rather than skips.
- **Fix:** build the probe and the traced `PDEparabolic` variant as CMake targets
  (for example with a `-DGEMINI_TRACE_TR` define).

**T3 — Medium — ●: the midpoint pipeline can pass vacuously.**
- **Evidence:**
  - `analyze_midpoint_diffusion.py` passes with zero cases, because `all([])` is True.
  - `trace_diffusion_stages.py` passes with empty `comparisons`.
- **Fix:** assert the expected inventory and non-empty traces.

**T4 — Medium — ●: the ledger checkers accept an inflated `scale`.**
- **Where:** `check_transport.py:94,101`; the same pattern is in `check_sources.py:75`
  and `check_energy_operators.py:35`
- **Evidence:** a ledger with 48 particles unaccounted per species and `scale=1e15`
  passes.
- **Fix:** recompute the scale, `max(|before|,|after|,|source|,|outward|,|cleanup|)`,

**T5 — Medium — ●: recorded metrics are not gated, and one tolerance is loose.**

**T6 — Medium — ●: reference data integrity.**

## 6. Recommended plan

### Phase 0 — hygiene, low risk, no numerical change

- **Untrack build leftovers:** remove the root `CMakeCache.txt`, `CMakeFiles/`,
  `corrections.patch` and `myrun`, and extend `.gitignore` (B1, B8, B13).
- **CMake guards:** add the in-source build guard (B5), restore the executable bits
  (B8), and add the `reader` link dependencies (B6).
- **HWM14:** fix the configure path and add an `hwm14-unit` CI job (B2).
- **Fail closed:** the memory gate (B4) and the negative tests (T1).
- **C API:** fix the `solar_ionization_C` prototype (C2) and the dump rank (C3).

### Phase 1 — correctness, needs science review and a reference refresh

- **Reporting:** file upstream issues for P1–P4 and P5, with minimal reproducers.
- **Remediation:** fix them on a dedicated branch with before/after reference
  comparisons and case-owner sign-off.
- **Error handling:** add `gemini_abort` with `MPI_Abort`, and replace root-only
  `error stop` calls inside MPI context (C1).
- **Solver change:** decide whether N1 is accepted as a default-path change, and record
  the nine-case native run.

### Phase 2 — qualification integrity

- **Dependency of record:** reconcile `libraries.json` with the inventory, add a CI
  comparison check, pin the nested MUMPS hash and add a mirror (B3, B10).
- **Provenance:** fix B9, and stamp build options (midpoint, sanitizers, models,
  dependency hashes) into the outputs (N6).
- **Probe builds:** build the physics probes through CMake rather than scraping commands
  (T2), and make the analyzers fail on empty inventories with gated metrics (T3–T5).
- **Pinning:** one hash-locked Python file (B11), SHA-pinned actions with Dependabot
  (B7), and CI triggers that cover scripts and PRs (B15).

### Phase 3 — enhancements that match the project's intent

- **C coupling API:**
  - an `integer(C_INT)` status channel on every wrapper, following the AGENTS.md
    convention;
  - explicit array dimensions or a sized work handle (C7);
  - ownership and call order documented in `gemini3d.h`;
  - generated prototype/arity and `offsetof` ABI tests.
- **Conservative physics options:** opt-in `pair_exchange` wiring (N5/P8), a pairwise
  conservative chemistry update with a cross-species ion-inventory ledger (P7), and an
  electron midpoint fixture (N3).
- **Hyperbolic test suite:** close the TODO.md item (T8).
- **Non-gating CI matrix:** HWM14-unit, midpoint ON, Unix Makefiles, and a
  shared-library plus installed-package consumer (B14, C16).
- **Restart robustness:** zero-initialize all state (C5), set the publication file mode
  (C4), and add an optional payload SHA-256 in the sidecar metadata.
- **Usability:** implement `gemini3d.run -n` with a `cpu_count()` fallback (C8), fix
  the magcalc time parsing (C9), and correct the input/output docs (C13).

## 7. Checked and found sound

- AGENTS.md `integer(C_INT)` boolean convention across all built `bind(C)` interfaces,
  and the `struct params` layout.
- The new OBJECT libraries (`nonlinear_diffusion`, the `diffusion_features`
  `configure_file`, `pair_exchange`) are correctly wired into both the MPI and non-MPI
  libraries.
- The `midpoint_TRBDF23D` time-centering (second order; the applied step starts from
  `Tⁿ`; the ledger stays flux-consistent).
- The `pair_exchange` conservation algebra.
- The coulomb Φ series.
- The `restart_runtime` rank, layout, generation and finite checks, the atomic publish
  ordering, and the sidecar prefix sanitization (apart from C4/C5/C11).
- All workflows declare `permissions: contents: read`.
- The POSIX launcher quoting is injection-safe.
- Full-grid integer overflow is not a practical risk in the C++/MPI paths. The
  exception is `elliptic3d.f90` `lPhi=lx1*lx2*lx3` (`potsolve=3`), which deserves a
  64-bit check.
